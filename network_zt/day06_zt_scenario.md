# A사 Zero Trust 적용 방안
## 5대 원칙 적용 방안
- ID: 모든 접속에 MFA를 적용해 비밀번호만으로 로그인하지 못하게 함
- Device: 등록하고 보안 점검한 기기만 정산 포털에 접속하게 함
- Network: 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다
- Application: 부서별 담당 자원만 접근하도록 앱 권한을 나눔
- Policy: 새벽·해외 접속, 20건 이상 조회에 위험 점수를 줘 추가 인증하거나 차단함
## 판단과 집행
- PDP(결정): 요청의 필수 조건과 위험 점수를 보고 허용·추가확인·거부를 정함
- PEP(집행): 정산 포털 앞에서 결정대로 통과·추가 인증·차단하고 로그를 남김
## 흐름도
```
사용자 --요청--> PEP --문의--> PDP
                                | 1. 재직 여부·등록 기기·접근 권한 확인, 조건에 안 맞으면 거부
                                | 2. 위험 점수 합산 (기기 상태, 국가, 시각, MFA, 조회량)
                                | 3. 50 이상 거부 / 20 이상 50 미만 추가확인 / 20 미만 허용
PEP <--결정-- PDP
PEP: 허용 --> 앱 접속 / 추가확인 --> MFA 요구 / 거부 --> 차단
각 결과는 로그에 기록
```
## 최소권한 기준 (목록에 없으면 거부)
- 재무팀: SETTLE(정산 내역)만
- 영업팀: SALES(영업 실적)만
- 서비스 계정 batch-night: SETTLE, 매일 02:00 정산 집계만
## 스코어링 결과
- 항목별 점수: MFA 10 / 기기 5 / 최소권한 15 / 세그멘테이션 0 / 위험기반인증 0
- 총점: 30 / 100
- 먼저 올릴 항목과 이유: 기기 등록과 보안 점검, 미등록 기기에서 새벽에 정산 120건을 조회했고 기기 점검 비율도 25%라 먼저 올려야 함
