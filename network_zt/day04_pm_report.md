SYN/ACK가 올 때: TCP 연결은 정상이므로 방화벽이나 포트 문제가 아니며, 서버 응용 프로그램 오류나 HTTP 응답 처리 등 상위 계층을 먼저 확인

### 문제 6-1 · 학원 방화벽은 허용 목록일까 차단 목록일까

- (가) 포트 443 · 445 · 3389 마다 「열림 · 드롭 · 거부」 판정과 근거(`curl` 문구 · Wireshark 화면)를 한 줄씩 적어 주세요.

  - 답:

445: 드롭 - curl: (28) Connection timed out after 5007 milliseconds,
3389: 드롭 - curl: (28) Operation timed out after 5002 milliseconds with 0 bytes received, curl은 타임아웃이지만 와이어 샤크에 TCP의 3-way handshake는 정상적으로 진행됨
- (나) 🔍 이 결과로 보면 학원 방화벽은 허용 목록과 차단 목록 가운데 어느 쪽에 가까운가요? 근거가 된 포트를 들어 적어 주세요.
  - 쓸 내용: ① 허용 목록 / 차단 목록 / 알 수 없음 가운데 하나 ② 근거가 된 포트와 그 결과 ③ 안내 6.1 표의 어느 줄과 맞는지
  - 답: 
차단 목록 또는 알 수 없음
443과 445는 드롭되었지만 3389는 curl 타임아웃과 무관하게 와이어샤크에서 TCP 3-way handshake가 정상 진행되어 방화벽을 통과함
관리용 포트인 3389가 열린 것으로 보아 차단 목록에 가깝고, 기준점인 443 웹까지 드롭된 것으로 보면 사이트 자체가 차단되어 알 수 없음으로도 볼 수 있음

- (다-1) 포트 세 개만 보고 내린 판단에는 어떤 한계가 있을까요? 더 확실하게 알려면 무엇을 더 해야 할까요?
  - 쓸 내용: ① 한계 한 가지 ② 더 해야 할 시험 한 가지
  - 답: 전체 65,535 개 포트 중 3개만 시험했고, 목적지가 portquiz.net 하나뿐이라 방화벽이 목적지별로 다르게 막는지는 알 수 없음 더 확실하려면 포트를 더 많이 시험하고, 다른 목적지에서도 같은지 확인 필요

- (다-2) 6번 필터(`tcp.flags.syn == 1 && tcp.flags.ack == 0`)로 바꾸니 2번 필터 화면에서 어떤 패킷이 사라졌나요? 한 PC 가 여러 포트로 연결을 시작한 것을 찾을 때 이 필터를 쓰는 이유는 무엇일까요?
  - 쓸 내용: ① 사라진 패킷의 종류 ② 시작 SYN 만 모아 볼 때 알 수 있는 것
  - 답: 상대방에게 온 [SYN, ACK]와 그 이후 패킷들, 한 출발지 PC가 몇 개의 서로 다른 대상 포트로 연결을 시도(포트 스캔)했는지 출발 기준 시도 횟수를 명확하게 파악할 수 있음
