- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답: Docker version 29.8.2, build 7fc2dff
- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답: 
1. 터미널의 의 docker 명령이 엔진에 요청(클라이언트 -요청-> 엔진)
2. 엔진이 hello-world 이미지가 pc에 없어서 Docker Hub에서 받음
3. 받은 이미지로 컨테이너를 만들어 실행
4. 컨테이너가 만든 글자를 엔진이 터미널로 보내 화면에 출력

- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답: docker iamges 에서 보인건 hello-world 이미지고 받아 둔 읽기 전용 묶음, 컨테이너를 지워도 남음
  ps -a 에서 보인건 컨테이너
  이미지는 해당하는 패키지와 그 버전들의 목록, 컨테이너는 그 기준으로 실행한 것
- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답: 
IMAGE는 hello-world:latest - 이미지 이름과 태그
ID는 11a3eb1597e8 - 고유 번호
EXTRA는 U - 이미지로 만든 컨테이너가 있다는 뜻
```
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   11a3eb1597e8       25.9kB         9.49kB    U
```

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답: 
STATUS는 Exited (0) 4 minutes ago 정상으로 종료, 0은 오류 없이 끝났다는 번호
PORTS는 비어있음 - 내 PC와 연결된 포트가 없다
NAMES는 serene_cannon - 무작위 이름 --name 을 주지 않아 생성
IMAGE는 hello-world - 이 컨테이너가 해당 이미지로 만들어졌다는 뜻
```
CONTAINER ID   IMAGE               COMMAND                  CREATED         STATUS                      PORTS     NAMES
16c3160ec650   hello-world         "/hello"                 4 minutes ago   Exited (0) 4 minutes ago              serene_cannon
```

### 문제 6-2 · 컨테이너 안을 들여다보고, 끄고, 지우기

- (가) 컨테이너 안에서 `ls /usr/share/nginx/html` 로 본 파일 이름을 모두 적고, 그중 브라우저의 첫 화면이 어느 파일인지 적어 주세요.
  - 쓸 내용: ① 파일 이름 모두 ② 첫 화면 파일
  - 답: 50x.html  index.html, index.html
- (나) 🔍 `docker stop web` 뒤에 `docker ps` 와 `docker ps -a` 에 각각 `web` 이 보이나요? 차이를 설명해 주세요.
  - 쓸 내용: ① stop 뒤 ps 에 보이는지 ② ps -a 에 보이는지 ③ 차이의 이유
  - 답: docker ps 명령은 실행중인 컨테이너가 없어서 안나오고, docker ps -a은 전체 컨테이너 까지 보여줘서
- (다) 🔍 같은 이름으로 다시 `run` 했을 때 나온 오류 문구와, `docker rm` 이 필요한 이유를 적어 주세요.
  - 쓸 내용: ① 오류 문구 ② rm 이 필요한 이유
  - 답: 
docker: Error response from daemon: Conflict. The container name "/web" is already in use by container "ad5fec683bac6fefab47026d36f1a0827ca4b0b0bc5aecb7d6f060647efab010". You have to remove (or rename) that container to be able to reuse that name.
이름이 중복되서 에러가 났고 Docker 컨테이너는 실행이 종료되거나 중지되더라도 자동으로 삭제되지 않고 정지 상태로 디스크에 그대로 남아 이름과 자원을 차지 하고 있기 때문에 더 이상 사용안하거나 패키지 변경 등으로 인해 동일한 이름의 새 컨테이너를 등록하려면 컨테이너를 삭제해야 함

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답: inside, Welcome to nginx! 이하
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답: 
컨테이너는 이미지에서 새로 만들어지고, 지우면 컨테이너 안에서 바꾼 파일도 같이 사라짐
-v 로 내 PC의 폴더를 연결하면 파일은 내 PC에 있고 컨테이너는 그걸 읽음
컨테이너를 지웠다 다시 켜도 파일은 그대로 유지, 고치면 서버에 바로 반영
- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답: Welcome to nginx! 이하, -v 뒤의 컨테이너 쪽 경로(/usr/share/nginx/html)를 윈도우 경로(C:/Program Files/Git/usr/share/nginx/html)로 바꿔서 잘못된 곳으로 연결되서
