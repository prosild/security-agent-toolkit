- 리눅스의 특징
(1) 오픈소스 소프트웨어
리눅스는 GPL(General Public License) 라이선스로 배포되며, 누구나 소스 코드를 확인하고 수정할 수 있습니다. 따라서 사용자와 개발자들이 자유롭게 시스템을 개선하거나 자신만의 용도에 맞게 변경할 수 있습니다.

(2) 다중 사용자 및 작업
리눅스는 유닉스의 영향을 받아 다중 사용자(Multi-user)와 다중 작업(Mulitasking) 환경을 기본으로 지원합니다. 즉, 여러 프로그램이 동시에 실행될 수 있으며, 여러 사용자가 동시에 시스템에 접근해 작업할 수 있습니다.

(3) 고성능 / 안정성 / 보안성
리눅스는 서버 운영체제로 안전성과 성능이 우수합니다. 시스템이 장시간 구동되어도 성능 저하가 적고, 대규모 시스템에서도 원활하게 동작합니다. 또한 파일 및 시스템 권한 관리가 철저하고, 제한된 사용자만 시스템 변경을 수행할 수 있어 보안성이 강합니다.

(4) 다양한 배포판
리눅스는 다양한 배포판 형태로 제공됩니다. 배포판은 리눅스 커널에 필요한 프로그램을 선택적으로 묶어 하나의 운영체제로 제공하는 것을 의미합니다. 유명한 배포판으로는 우분투(Ubuntu), 데비안(Debian), 페도라(Fedora), 레드햇(Red Hat) 등이 있으며 이 외에도 수천가지 배포판이 특정 용도와 환경에 맞게 최적화되어 사용됩니다.

(5) 방대한 커뮤니티
리눅스는 방대한 커뮤니티에 의해 개발되고 지원됩니다. 전 세계의 개발자와 사용자가 프로그램의 오류를 보고하고 개선 사항을 제안하며, 다양한 문서가 제공되어 사용자들이 도움을 받을 수 있습니다. 또한 개발자는 리눅스 시스템에 기여하는 것에 자부심을 갖기 때문에 개발자의 실력 향상과 동기 부여에 기여하고 있습니다.

리눅스는 서버 및 클라우드 인프라, 슈퍼컴퓨터, 임베디드 시스템, 모바일 기기 등 다양한 분야에서 핵심적인 역할을 하고 있습니다. 오픈 소스라는 강점과 함께 높은 안정성과 유연성 덕분에 여러 산업과 연구 분야에서 필수적인 운영체제로 자리잡고 있습니다. 예를 들어, 전 세계의 많은 웹 서버와 데이터베이스 서버가 리눅스 기반으로 운영됩니다. 또한 AWS(Amazon Web Service), 구글 클라우드, MS의 애저(Azure) 같은 클라우드 서비스 제공 업체들은 리눅스를 기반으로 인프라를 구축하고 있습니다. 리눅스는 슈퍼 컴퓨터에서 가장 많이 사용되는 운영체제로 전 세계 슈퍼 컴퓨터의 대부분이 리눅스 기반 시스템으로 구동합니다.




- Git
Git은 분산 버전 관리 시스템(DVCS: Distributed Version Control System)으로, 소프트웨어 개발 프로젝트에서 소스 코드의 변경 이력을 관리하고 협업을 원활하게 하기 위해 사용된다. Linus Torvalds가 2005년에 개발한 Git은 다양한 프로젝트에서 널리 사용되고 있으며, 특히 오픈 소스 커뮤니티에서 큰 인기를 끌고 있다.

Git의 기본 용어
저장소(Repository): 프로젝트의 모든 파일과 변경 이력을 저장하는 장소다. 로컬 저장소와 원격 저장소가 있다.
커밋(Commit): 변경 사항을 기록하는 행위로, 특정 시점의 프로젝트 상태를 저장한다.
브랜치(Branch): 독립적인 작업 공간으로, 새로운 기능 개발이나 버그 수정 등을 위해 사용된다.
머지(Merge): 브랜치를 합치는 작업으로, 여러 브랜치에서의 변경 사항을 하나로 통합한다.
풀(Pull): 원격 저장소의 변경 사항을 로컬 저장소로 가져오는 작업이다.
푸시(Push): 로컬 저장소의 변경 사항을 원격 저장소에 업로드하는 작업이다.



- GitHub
GitHub는 Git 저장소를 호스팅하고 협업할 수 있는 웹 기반 플랫폼이다.

GitHub란?
Git 저장소 호스팅 서비스

GitHub의 기본 기능은 Git 저장소를 클라우드에 저장하고 관리하는 것이다. 로컬에서 Git으로 관리하던 코드를 GitHub에 업로드하면, 어디서든 접근할 수 있고 다른 사람과 공유할 수 있다. 무료 계정으로도 무제한의 공개 저장소와 비공개 저장소를 만들 수 있다.

협업 플랫폼 - GitHub는 단순한 저장소를 넘어 개발자들이 함께 일할 수 있는 다양한 도구를 제공한다.

Pull Request: 코드 변경사항을 제안하고 리뷰받을 수 있다
Issues: 버그 추적, 기능 요청, 작업 관리를 할 수 있다
Projects: 칸반 보드로 작업을 시각화하고 관리할 수 있다
Discussions: 프로젝트에 대한 질문과 논의를 할 수 있다
GitHub Actions: CI/CD 파이프라인을 구축할 수 있다
GitHub Pages: 정적 웹사이트를 무료로 호스팅할 수 있다
GitHub와 Git의 관계
Git과 GitHub는 서로 다른 것이다.

Git: 버전 관리 시스템 (소프트웨어)
GitHub: Git 저장소 호스팅 서비스 (웹 플랫폼)
Git은 로컬에서 독립적으로 사용할 수 있으며, GitHub 없이도 완전히 작동한다. GitHub는 Git을 기반으로 하지만, 웹 인터페이스와 협업 기능을 추가로 제공한다.



- GitHub를 사용하는 이유

1. 협업과 프로젝트 가시성
누가 어떤 작업을 하고 있는지 한눈에 파악할 수 있다
프로젝트의 전반적인 진행 상황을 추적할 수 있다
신규 참여자가 프로젝트를 쉽게 이해할 수 있다
Pull Request를 통한 체계적인 코드 리뷰가 가능하다

2. 품질 보증과 자동화
변경사항을 배포 전에 검증할 수 있다
CI/CD를 통한 자동화된 테스트로 회귀를 방지할 수 있다
코드 리뷰로 버그를 사전에 발견할 수 있다
GitHub Actions, GitLab CI 등의 자동화 도구와 쉽게 연동된다

3. 지식 공유와 문서화
코드와 문서가 체계적으로 축적된다
이슈 트래커를 통해 결정 사항과 그 이유가 기록으로 남는다
팀의 노하우가 자연스럽게 공유된다
Wiki, README 등을 통한 문서 관리가 용이하다

4. 백업과 장애 복구
중앙 저장소가 자동으로 백업 역할을 한다
서버 장애 시에도 쉽게 복구할 수 있다
여러 개발자가 전체 이력을 보유하고 있어 데이터 손실 위험이 낮다

5. 권한 관리
중앙에서 체계적인 권한 관리가 가능하다
브랜치 보호 규칙을 설정할 수 있다
누가 어떤 작업을 할 수 있는지 명확히 제어할 수 있다

- Git Bash
Git Bash는 Windows 환경에서 Unix/Linux 스타일의 커맨드 라인 경험을 제공하는 애플리케이션이다. 이는 Git 명령어 뿐만 아니라 기본적인 Bash 셸 명령어를 사용할 수 있게 해주어, Windows 사용자들이 보다 편리하게 Git을 사용할 수 있도록 돕는다.

왜 Git Bash를 사용해야 할까?
Git Bash를 반드시 사용해야 하는 것은 아니지만, Git Bash 사용에는 다음과 같은 이점이 있다.

통합 환경 제공 - Git Bash는 Git 리포지토리를 관리할 수 있는 Bash 환경과 함께 Git을 설치하므로, 다른 도구를 별도로 설치할 필요가 없다.
향상된 스크립팅 기능 - Bash 쉘은 복잡한 스크립트를 작성할 수 있는 기능을 제공하여, 자동화된 작업을 쉽게 처리할 수 있다.
Linux 명령어 지원 - Linux 사용자에게 익숙한 명령어를 Windows에서도 사용할 수 있어, 다양한 시스템 간 작업의 일관성을 유지할 수 있다.
